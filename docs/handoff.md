# GridAid handoff for Arjun

## Start here

The tested planning application lives in **`backend/` + `frontend/`**. Use the commands below from the repository root and open **http://127.0.0.1:8000/**. It needs no accounts, API keys, paid services or data downloads after initial dependency installation.

The shared repository already contained a separate **Base44 UI in root `src/`**, root `package.json`, and `base44/`. That code and its Git history have been preserved. It currently uses synthetic JavaScript data/heuristics in `src/lib/gridaid/`, not the verified FastAPI engine. Its original setup instructions are archived in [base44_setup_original.md](base44_setup_original.md). Root `npm run dev`/Base44 instructions do **not** start the tested app. No Base44 build, hosted auth, publishing or production-data operations were executed for this handoff.

Repository: `https://github.com/sashwatc/Gridaid.git`; shared branch: **`main`**. The handoff commits build on the existing remote history; no force-push or public deployment is required.

## Exact clean setup and run

Prerequisites: macOS or Linux, Python 3.10+ for bootstrap, Node 22.12+ and npm, Git, and internet for dependency/browser installation. The actual test platform is macOS arm64, Python 3.12.15, Node 26.3.1, npm 11.16.0. Other platforms have not been verified. uv downloads project Python 3.12 if needed.

```bash
git clone --branch main https://github.com/sashwatc/Gridaid.git
cd Gridaid
python3 -m venv .bootstrap
.bootstrap/bin/pip install uv==0.13.5
.bootstrap/bin/uv sync --frozen
npm --prefix frontend ci
npm --prefix frontend run build
./scripts/serve.sh
```

Open **http://127.0.0.1:8000/**. Keep that terminal running. `Ctrl-C` stops it. Keep a single server worker: in-memory run/rate/concurrency state is local to that process. The launcher binds to loopback by default and needs `frontend/dist/index.html`, generated by the build.

Optional exported variables: `GRIDAID_HOST=127.0.0.1`, `GRIDAID_PORT=8000`, and `GRIDAID_CORS=http://127.0.0.1:5173,http://localhost:5173`. `.env.example` is a public sample; scripts do not automatically load `.env`. Never commit local credentials. Changing the port also requires changing the browser-test base URL/Vite proxy; leave 8000 for documented verification.

For frontend editing, run these in separate terminals instead:

```bash
# Terminal 1, root
.venv/bin/uvicorn backend.api.app:app --host 127.0.0.1 --port 8000
```

```bash
# Terminal 2, root
npm --prefix frontend run dev
```

Open Vite's printed loopback URL (usually 5173). It proxies `/api` to port 8000. Do not simultaneously run a second backend on 8000. Restart after Python changes; rebuild before using the production UI served by FastAPI.

## Verification

With `./scripts/serve.sh` running on port 8000, use a second terminal:

```bash
npm --prefix frontend exec -- playwright install chromium
./scripts/verify.sh
```

On Linux, browser system libraries may be required; `npm --prefix frontend exec -- playwright install --with-deps chromium` can install them with appropriate OS privileges. This Linux path is documented but unverified here.

Individual checks:

```bash
.venv/bin/pytest -q
npm --prefix frontend run typecheck
npm --prefix frontend run build
npm --prefix frontend run test:browser
curl --fail http://127.0.0.1:8000/api/health
```

`verify.sh` regenerates the synthetic fixture, tests the backend, builds/type-checks the UI, and runs actual Chromium workflows. It fails if no server is available. Browser tests include real/fixture API-number comparisons, loading/errors, stale controls, map layers, explanations, and the in-flight trial-count race. Raw output/screenshots are regenerated under ignored `artifacts/`.

## Architecture and current implementation

| Location | Responsibility / status |
|---|---|
| `backend/api/app.py`, `schemas.py` | FastAPI, strict Pydantic requests/results, baseline/static/resilient/evaluation/simulation/ML/preset/export routes, bounded run store |
| `backend/services/routing.py`, `data.py`, `geography.py` | Validated directed multigraph, custom Dijkstra, versioned read-only matrices, legal partial-edge arrivals, original Census points and explicit assumed access |
| `optimization.py`, `resilience.py` | Deterministic/random/greedy baselines; SCIP coverage and p-median; **one shared placement** across scenarios with default 0.6 average + 0.4 minimum normalized coverage |
| `scenarios.py`, `metrics.py`, `simulation.py`, `explanations.py` | Six original scenarios plus winter/closure portfolio, unreachable-aware metrics, paired seeded trials, computed contributions/redundancy/stability |
| `backend/security.py` | Body/rate/solver bounds, two active jobs, killable whole-job deadline, cancellation-safe capacity, CORS/headers/safe errors |
| `ml/` | Offline real retrospective tract-month model and separate labeled synthetic experiment; no runtime model deserialization |
| `frontend/src/` | Connected React 19/TypeScript/Vite/Leaflet app; working map, controls, comparisons, distributions, explanations and methodology/security/model UI |
| root `src/` | Preserved Base44 React 18 design/prototype; **not** integrated with the validated engine and not covered by the full-stack test/audit claims |
| `scripts/`, `tests/`, `docs/` | Rebuild/experiment/verification utilities, independent mathematical/security/browser tests and source traceability |

The working app is a local planning simulator, not dispatch software. JSON uses `null` with explicit unreachable shares for infinite travel statistics. P-median's unreachable penalty is separately labeled. Do not reintroduce frontend-calculated substitute metrics or label feasible/heuristic results optimal.

| `data/processed/matrices/` | **Ignored; not required** | Automatically rebuilt on demand; optionally `python -m scripts.precompute` |
| `data/processed/ml/*` including `.joblib`, training/risk Parquet | **Ignored; not required at runtime** | `python -m ml.train` for fixture; full real pipeline below for real artifacts. Runtime uses precomputed forecasts and never loads joblib |

| `.bootstrap/`, `.venv/`, `frontend/node_modules/`, `frontend/dist/`, `artifacts/` | **Ignored generated outputs** | Exact bootstrap/install/build/test commands above |

**No ignored file is required to run the documented app or its full verification suite.** Do not copy the developer's raw data, virtual environments or credentials into a new clone. The clean-checkout verification record below establishes this for the shipped files.

To expand the committed public snapshot locally without network data acquisition:

```bash
.venv/bin/python - <<'PY'
import gzip
from pathlib import Path
out = Path('data/processed/iowa.json')
out.parent.mkdir(parents=True, exist_ok=True)
out.write_bytes(gzip.decompress(Path('data/public/iowa.json.gz').read_bytes()))
PY
.venv/bin/python -m scripts.precompute
```

For a complete public-data/offline-model rebuild, stop the app first and run from root:

```bash
.venv/bin/python -m scripts.ingest
.venv/bin/python -m scripts.dot_snapshot
.venv/bin/python -m ml.train
.venv/bin/python -m ml.real_train
.venv/bin/python -m scripts.geography_audit
.venv/bin/python -m scripts.real_demo
.venv/bin/python -m scripts.precompute
```

`ingest` downloads dated Geofabrik OSM plus Census and resets the processed ML flag; `ml.real_train` then attaches evaluated risk and updates the compressed snapshot. `geography_audit` alone changes access/coordinates without retraining. `real_demo` must follow dataset changes because preset versions are checked. Restart the app and refresh the browser afterward. Review all changed data/model versions, source manifests and metrics before committing regenerated snapshots/reports.

Raw source hashes/dates/queries are recorded in `docs/*manifest.json` and `ml_real_metrics.json`. Upstream historical crash corrections can change a fresh training rebuild; byte-identical reproduction of old training artifacts requires the corresponding archived raw caches. Those large caches are not shipped. The **committed forecast snapshot** is the stable, credential-free demo input. Never repeatedly choose/tune models against the final test.

## Latest verified results and known limits

Latest application checkpoint: **52 backend tests passed; 4 Chromium tests passed; strict TypeScript/production build passed through `./scripts/verify.sh`**. Pip/npm scans for the **Python + `frontend/`** lockfiles reported zero known vulnerabilities; Bandit zero findings; secret flags were reviewed public identifiers. These results do not cover the preserved root Base44 package or a deployment. Current details and historical evidence are separated in [validation.md](validation.md), [audit.md](audit.md) and [requirements.md](requirements.md).

The real preset is four resources, Population, five minutes, 1.6 winter, central closure, 20 km/h access, normal/winter/closure/winter+closure. Static normal/average/worst: **78.220 / 50.736 / 23.616%**; resilient: **67.245 / 53.475 / 38.799%**. All 12 evaluated real cases are published, including four identical placements. See [walkthrough](real_data_demo.md) and [all-case table](real_data_results.md).

Limitations, in priority order:

1. Thirty-nine whole-tract representative points do not establish exact household coverage. Straight access connectors, including the 871 m maximum, are unverified paths; access speed materially changes results.
2. Truncated/static roads, speed defaults, omitted turn/capacity/dispatch effects, and assumed candidates/disruptions are not professionally calibrated. This is not all Scott County; see [geography.md](geography.md).
3. ML is a **January 2024 retrospective transportation forecast**, not current/general emergency risk. Historical reporting latency/revisions are unverified. Forest won validation; Poisson had lower final-test MAE (1.750 versus 1.775). Preserve that honest comparison and selection.
4. No human/expert study, operational validation or public HTTPS/HSTS/distributed-limit testing. Native live 511 access needs authorization. Full competition release gates remain unmet; video/submission/public deployment are not part of this handoff.
